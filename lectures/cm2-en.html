The mechanism

The k-of-n quorum

one question
→
n models from distinct families
→
n values
→
kept if k values are equal
  • k is a strict majority: more than half of n.
  • An unavailable model stays in n and does not vote.
  • Two accesses to the same model family count as one vote.

Without a majority

Abstaining is an answer

When no value reaches k, the system returns “no majority” with the values received. It does not choose the most frequent one, it does not draw lots.

Fictional example: three models return 101, 103 and 107. With k=2 and n=3, no value reaches the threshold: the quorum abstains.

What the quorum proves

The quorum exposes disagreement, it does not create truth

Agreement between models is an absence of disagreement. Models trained on similar data get it wrong in the same way; their agreement says nothing about the value.

A visible disagreement triggers a check. A false agreement passes for a certainty and is checked by nobody: it is the most dangerous output of a system with several models.

What protects

Four safeguards, from the cheapest to the most expensive

  • A panel of distinct families: models from different vendors get it wrong together less often.
  • A deterministic check where one exists: the query is executed, the value is compared, a constraint is verified.
  • An escalation to a more capable model on disagreement or on abstention.
  • A human review when the answer carries consequences: health, investment, legal decision, amount paid out.
Complements

Field-by-field agreement, escalation on disagreement

  • Field by field: for an answer with several values (a ranking, a breakdown), the vote applies to each field; partial agreement is kept and disagreement is localised.
  • Escalation: an inexpensive model answers first; a second one confirms; the capable model is called only in case of disagreement. Most questions stop at the first level.

Escalation is where the quorum and routing meet: it buys checking where the request justifies it.

Complements

The judge model and its limits

Asking a model to judge the answers of the others is possible. This judge has its own error margin, often shares the biases of the models it judges and prefers a well-written answer to a correct one.

A judge model sorts; it does not certify. An independently checked reference lets you verify the result on the specified data.

Each step is taken only if the previous one cannot serve the request within its deadline. A quota's refill date does not prove availability: it is rechecked on waking.

On the user's side

One interface, one answer

The user asks their question. The service reads the request, chooses the resource, applies the checking, returns the answer or the abstention. None of this machinery is asked of the user.

What the company has to maintain in the background: the table of resources, their availability, their price, the rule, and the trace of each decision for the audit.
