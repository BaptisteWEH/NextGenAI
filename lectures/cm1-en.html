What you will be able to do in December

Two decisions, and the evidence that grounds them

  • For a given request, choose the cheapest model that remains up to its difficulty, and write the rule that applies this choice without the user having to make it.
  • When the answer carries consequences, query several models and keep only a majority, with abstention when no majority exists and independent checking of the result.
  • In both cases, check an answer against a reference computed without a model, and read the trace that says what happened.

The finding

A wrong figure looks like a right one

A model output is a draw: the model computes a probability for each next word, then draws one. Two draws differ. A wrong answer is written with the same confidence as a right one.

A numerical answer needs a check. Execute SQL on the database and independently verify the reference before comparing model answers. This identifies errors on the cases studied.

Where the gap comes from

Three settings, and a version that moves

  • Temperature and top-p set the share of randomness in the draw. At temperature 0, the model takes the most probable word; two words that are almost tied can still flip from one call to the next.
  • The context: the same question with a written schema, units and conventions produces a different answer from the bare question.
  • The version: the model served under the same name changes without notice. A measurement has a date.
The lab session sets the temperature to 0, sends the same prompt to all models and dates each trace: the remaining gaps are attributable to the model.

A request that can wait is handled on capacity already paid for, when the quota comes back. An urgent request is handled on the available paid route. The service handles this capacity management; the user asks their question.

Allocation

The resource that is up to the request

Giving an addition to a senior engineer yields a correct result, paid at the senior engineer's rate. Giving an expert assessment to an intern yields a fast result, often wrong. Assigning each request to the resource whose capability matches its difficulty is an allocation problem, the same as in team management.

With models, the rule is written and executed automatically: this is the first skill of the module.

  • Quota exhausted and deferrable request: wait for the refill.
  • Urgency: the available paid route within the budget.
  • No eligible resource: abstention, or handover to a person.

The rule runs in the background. The user sees a single interface and an answer.

Decision 2

Cross-checking: the k-of-n quorum

When the answer carries consequences, n models receive the same question; a value is kept if at least k of them return it. Without a majority, the system abstains and says so.

The quorum costs n calls instead of one. It is reserved for requests where an error costs more: health, investment, legal decision, amount paid out.
