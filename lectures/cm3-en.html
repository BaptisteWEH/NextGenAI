Wait or pay

The deadline is a resource

A request that can wait is handled on the included capacity when the quota comes back. An urgent request is handled on the paid route available, within the budget of its type. The rule writes the deadline at the same rank as difficulty and stakes.

In the portfolio presented, each type of request carries a spending cap, from 0 to 35 euros, and the month is capped at 70 euros. A cap that is reached stops cleanly and resumes when a subscription comes back.

The decision rule

A check is justified by the cost of the error it avoids

A check is worth it when its cost per question stays below the cost of an error multiplied by the frequency of the errors it avoids.
  • One error in a hundred at 10 euros to correct: a check at 0.05 euro per question is justified; a check at 0.50 euro is not.
  • One error in a hundred at 10,000 euros of harm: a check at 5 euros per question is justified.

The frequency of errors comes from your traces; the cost of an error comes from the use case. Neither of the two comes from the model.

Experience report

A real portfolio: sixty pairs, five groups, one rule

  • Every request receives a type, from demanding judgement to the task without a model; the type sets the capability group and a spending cap.
  • Within the group, the order is: available subscription, from the lowest effective cost to the highest, then free models, then paid routes under a price bar.
  • Quota exhausted: the request waits for the window to come back and measures availability again on waking. Cap reached: clean stop, resumption on a subscription.

Survey of 28 September 2026: 60 model and access pairs, public index, price and effective cost per line; the table is in the kit.

Experience report

A consensus system, and its shutdown

An assistant in production queried several models in parallel and kept an answer only by consensus, settled by a deterministic check. Disagreement served as a signal.

When standard models reached the required level on their own, the extra cost of consensus no longer bought any trust. The system was shut down. Redundancy is worth paying for as long as it reduces the risk.

Agentic orchestration protocols

What MCP standardises

The Model Context Protocol (MCP) defines how a model discovers and calls tools, data sources and services: a server exposes described tools, a client presents them to the model, the model requests a call, the client executes it and returns the result.

What the protocol does not decide: which model to call, which check to apply, what the call costs. Those decisions remain those of the service.

Agentic orchestration protocols

When a production system gains from it

  • Several models have to reach the same tools: a single description replaces one integration per model.
  • The service wants to trace and check every tool call: the MCP client is the point of passage.
  • The tools change faster than the service: the interface stays stable.

In the guiding case, read-only SQL execution is a tool; the sandbox is its check. An MCP server would expose it in the same way to all the models of the portfolio.
